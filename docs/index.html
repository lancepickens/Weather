Weather

Astronomical weather forecasting, calibrated against webcam ground truth

Overview Webcam Analyzer

What this project is

Two coupled command-line tools that together produce — and validate — a per-hour cloud forecast for an amateur-astronomy observing site. The default site is Henry W. Coe State Park (793 m, on the Bay Area marine-layer ceiling), but anything in sites.json works.

ToolRoleWhere
cloud_height_predictor.py Pulls DWD ICON forecast data via Open-Meteo, computes the cloud base, restricts to astronomical night, and emits a per-hour table with flags. repo root
webcam_analyzer/ Pip-installable subproject. Downloads AlertCalifornia webcam frames, counts catalog stars actually visible in each frame, and reports an hourly cloud score. Used as ground truth to calibrate the predictor. webcam_analyzer/

The data flow

Why two tools, not one

The original predictor consulted a single ICON grid cell at the observing coordinates. On the night of 2026-05-14 it reported clear skies, while Astrospheric (same ICON source) showed 100% cloud cover at the same coordinates. The reason was a known artifact: Open-Meteo snaps each requested point to one ~13 km grid cell with no interpolation, and at coastal/inland boundaries that single cell can land in an anomalous "dry island" while every neighbour is socked in.

A 3×3 neighbour-ring fix (described on this page below) eliminated the false-clear case but introduced the opposite false-overcast case at marine-layer-ceiling sites like Coe. To break that tie a physical ground truth was needed — somewhere the actual sky can be observed. That's what the webcam analyzer provides.

The predictor

Ring-max aggregation

cloud_height_predictor.py fetches a 3×3 neighbour ring around the configured coordinate at offsets of ±0.15° (≈17 km, large enough to guarantee distinct ICON cells in every direction). RH, dewpoint, and cloud-cover (with low/mid/high splits) are taken as the element-wise max across the ring; temperature and is_day come from the center cell. The displayed Td may exceed the center T — that's intentional; the row represents three separate worst-case readings rather than one self-consistent point forecast.

Flags

The predictor emits up to four flags per hour. They are not mutually exclusive — the marine layer below flag exists specifically to reinterpret the conservative flags rather than override them.

FlagSourceMeaning
extinction ring-max LCL ≤ site elevation Cloud base sits at or below observer height somewhere in the ring.
below ridge ring-max LCL ≤ ridge_height_m Deck obscures the configured local horizon.
marine-layer risk ring-max RH > 90 % Saturated air anywhere in the ring.
marine layer below center RH < 70 % and center cover < 30 % and ring RH > 90 % Site sits at an inversion top: ring is socked in but the configured point is dry/clear. Conditions overhead are likely good.
Calibration source

The thresholds UNDERCAST_CENTER_RH_MAX_PCT = 70 and UNDERCAST_CENTER_COVER_MAX_PCT = 30 were set against the 2026-05-14/15 webcam capture at Coe: ring flagged full extinction every hour while the Axis-StarrCanyon1 camera (at the same elevation) confirmed clear skies overhead.

The webcam analyzer

The analyzer turns a 12-hour overnight timelapse into an hourly cloud score by counting stars that should be visible against stars that actually are. It runs as three CLIs because the slow parts shouldn't repeat:

  • webcam-fetch — download a rolling timelapse manifest.
  • webcam-calibrate — plate-solve once, reuse forever (the cam is fixed-pointing).
  • webcam-analyze — per-frame star detection vs catalog prediction.

The full pipeline, including how a 65° FOV is solved with astrometry.net indices that only cover 5–8°, lives on its own page: → Webcam Analyzer architecture.

Running it

# Forecast
./hc_cloud_forecast.sh                          # Henry Coe wrapper
python3 cloud_height_predictor.py --site henry-coe --nights 3

# Webcam ground truth — fetch + calibrate + analyze
./webcam_analyzer/run.sh                        # one-shot
./webcam_analyzer/run.sh --skip-fetch           # re-analyze cached frames
./webcam_analyzer/run.sh --recalibrate          # force new plate-solve
